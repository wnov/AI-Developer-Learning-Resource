# 实验 2：策略迭代 vs 价值迭代（验证模式，示范阶段）

目标：在实验 1 的网格世界上，比较策略迭代和价值迭代。代码由 AI 生成，你负责说明需求、写预测、设计独立检查，并用检查找出我植入的 bug。

- 资料：SB 4.3 Policy Iteration（书第 80 页，PDF 第 102 页，http://incompleteideas.net/book/RLbook2020.pdf#page=102）、4.4 Value Iteration（书第 82–83 页，PDF 第 104–105 页，http://incompleteideas.net/book/RLbook2020.pdf#page=104）。理论会话 S1.4、S1.5 之后再做。
- 模式：这是试点的验证模式（见 `plan.md`“协议待改”的 2026-10-01 试点条目），本次是**示范阶段**。我给出需求说明的模板和一个检查项样例，其余由你填写。
- 硬规则：每个独立检查的**原理和预期值由你给出**，AI 只负责把它写成代码。原理或预期值来自 AI 的检查不算独立。
- 代码生成：在本目录（`labs/1-pi-vi/`）里打开 Claude Code，把需求说明交给它，代码就写在本目录，你随时可以看。不要用本学习会话。根目录 CLAUDE.md 顶部的“编码模式”规则会让它只当编码助手，不读课程记录、不写 log。
- 题设脚本：实验前我会在本目录准备一个独立的短脚本，题设写在文件开头，改一个值就能重跑。AI 的实现不要调用这个脚本里的计算，否则你用它做检查就不独立了。

## 环境

和实验 1 相同（SB 例 4.1，见 `labs/1-policy-evaluation/README.md`）：4×4 网格，两个角是同一个终止状态 T，每步奖励 −1，γ = 1。另做一组 γ = 0.9。

## 第 1 步：需求说明

写一份交给 AI 的需求说明，下面是模板，每一项都要填：

```
算法：策略迭代（SB 4.3 算法框）和价值迭代（SB 4.4 算法框）
环境表示：
输入 / 输出（函数签名，返回哪些量）：
终止状态怎么处理：
收敛判定（策略迭代：评估内层用什么判定、外层什么时候停；价值迭代：用什么判定）：
同一状态有多个动作并列最优时，怎么选：
需要记录的量（用于对照）：
不允许的做法：
```

## 第 2 步：运行前的预测

写成数值或方向，不能只写“猜”。

1. 从等概率随机策略出发，策略迭代的外层要迭代几轮，策略才不再变化？
2. 价值迭代在 θ = 1e-4 时要扫描多少轮？
3. 两种算法最后得到的 v 和策略一样吗？如果有不一样的地方，可能是哪一类？
4. 把策略迭代内层的策略评估改成只扫描 k 轮（k = 1、2、3、不截断），外层轮数和最终结果怎么变？
5. γ 从 1 改成 0.9，上面 1、2 两题的数字怎么变？

## 第 3 步：检查项

每一项写四栏：

| 检查 | 原理和预期值（由你给出） | 能抓到哪类 bug | 抓不到哪类 bug |
| --- | --- | --- | --- |
| 样例：用实验 1 的 `policy_eval.py` 评估最终策略 | 实验 1 的代码是你自己写的、已验证过；对最终策略求 v_π，应与算法输出的 v 一致，最大误差低于 1e-6 | 策略和价值对不上，例如贪心取 argmax 时下标错位 | 两边共有的错误，例如环境的转移本身就错 |
| … | | | |

至少再写 3 项，并且至少一项不依赖任何代码，例如手算某个状态的值、书上的图。

## 第 4 步：生成、运行、对照

1. 把需求说明交给 AI 生成代码，放到本目录。
2. 运行，逐项对照第 2 步的预测和第 3 步的检查。预测错了的地方，先写出假设，再设计能区分假设的检验，每次只改一处。

## 第 5 步：植入 bug

你的检查都通过后，我会在一份副本里植入 2–3 个 bug，不告诉你位置和数量。你只用第 3 步的检查去找，记录：

- 抓到了哪几个，各由哪个检查抓到；
- 漏掉的那几个，为什么你的检查覆盖不到，应该补什么检查。

## 提交和评分

- 需求说明、预测、检查表、AI 生成的代码、运行输出，以及第 5 步的记录。
- 按排查流程的 5 条打分（示范阶段的分数作为基线，不影响等级）：
  1. 运行前有书面预测，写的是数值或方向；
  2. 至少一个独立检查，原理和预期值由你给出；
  3. 出现异常时先写假设，再设计能区分假设的检验，每次只改一处；
  4. 能说出每个检查覆盖哪类 bug、覆盖不到哪类；
  5. 结论落到机制上。
- 另外记录：植入的 bug 抓到几个，以及每个 bug 是谁先发现的。
